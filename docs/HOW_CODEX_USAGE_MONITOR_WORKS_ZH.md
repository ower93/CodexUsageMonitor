# Codex Usage Monitor 2.0：运行原理与计算规则

更新：2026-11-03。本文描述已在本机安装的 2.0.1 (10)，公开发布验收尚未完成。

## 三条数据链路不能混用

| 链路 | 方法与来源 | 边界 |
|---|---|---|
| 账户额度 | 本地 app-server 的 `account/rateLimits/read` | 由账户返回，不按 token 倒推 |
| 账户活动与最近聊天 | `account/usage/read`、`thread/list`，以及对应本机计数 | 方法不受支持时独立报错；最新聊天不等于正在操作的聊天 |
| 本机等值估算 | sessions / archived_sessions 的 JSONL 计数 → 冻结账本 → SQLite | 不保证覆盖其他机器、删除或缺失的日志 |

`usedPercent` 是已用比例，剩余为 `clamp(100 - usedPercent, 0...100)`。
优先读取多组 `rateLimitsByLimitId`，旧响应回退到单组 `rateLimits`。
窗口长度、重置时间、计划或可用重置次数缺失时保持未知，不补 0。

默认日志根目录为 `~/.codex`，支持 `CODEX_HOME`。
Finder 启动不一定继承终端环境变量，自定义目录须在实际启动方式中验证。
「数据状态」支持自定义 Codex 可执行文件，重启后生效；不会自动修改 Codex 认证或配置。
应用通过 `app-server --stdio` 复用登录，不直接读取/导出认证令牌；
helper 自身按 Codex 正常机制联网。因此本机优先不等于账户额度完全离线。
`session_index.jsonl` 只提供标题，不读取提示词来生成所谓智能洞察。

## 来源状态与刷新时间

额度、账户活动、聊天、本机费用各自记录状态、最后成功时间和错误。
首次读取为 loading；成功为 live；有上次数据但本次失败为 stale；
没有成功数据为 unavailable。只有显式 `--demo` 才显示虚构数据。
失败不能回退到演示值，null 不能当作 0。

菜单百分比只对应选中的额度组，旧数据带警示。
底部「额度更新」不是费用更新时间；各自的新鲜度到「数据状态」查看。

## token 与美元如何计算

累计计数的 `input_tokens` 包含缓存输入。分类有效的新用量按下式估算：

```text
普通输入 = input_tokens - cached_input_tokens
USD = (普通输入 × 输入单价
     + cached_input_tokens × 缓存输入单价
     + output_tokens × 输出单价) / 1,000,000
```

不重复叠加缓存输入，不按运行分钟推算 token。模型按事件上下文解析；
一个聊天切换模型时保留各自记录和价格。

累计计数与上次 checkpoint 做差，再检查分类是否与总增量一致。
缓存增量大于输入增量、分类不一致、计数回退或无法可靠分配时，
不会截断/强制归零或套用默认模型制造精确金额。
可保留的原始增量标异常并保持未计价；无法可靠摄入的情况进入采集问题列表。
没有可计价 token 时金额显示「—」，不是确认费用为零。

已有冻结记录不会被新逻辑悄悄重算；历史分类异常提示但保留原金额。
改善新摄入不等于所有旧记录通过重新核账。若要修正历史，应单独备份、对账、
记录修正原因并取得用户确认。

## 父子聊天

子聊天可能继承父累计计数，也可能从独立计数器开始。
解析器结合父线程、派生时刻和首个可靠计数判断基线，不一律从子计数减去父计数。
旧日志无法可靠判断时保守排除并展示原因，不猜测新增费用。

分析先汇总各聊天的独占记录，再组成父子组；展开后组总计等于成员之和。
不能把组总计与其孩子再次相加。循环、断链和不完整日志采用可检查的回退并披露缺口。

## 日期与价格冻结

- 本周从本机时区周一 00:00 起算；上周是前一个完整本地周。
- 同比周比较只比较对应数量的完整日，双方都不含今天。
- 账户「近 7 天」仍是 Codex 活动口径，不改成自然周。
- 本机生涯仅代表账本中保留的本机可见历史，不是跨设备账户总计。
- 账本日期是写入时的本地日期键。旅行切时区不会重写冻结历史；
  缺少可重建时间戳时不能保证按新时区重新分桶。

每条已计价记录保存分类、模型、日期、三个单价、价格版本和 USD。
新价格仅用于后续新记录。未计价历史不能随意按今天价格批量重估。
历史授权的 GPT-6 Astra 补估会保留备份与 `pricingBackfill` 的日期、原因、来源；
分类异常记录不参与补估。

## 存储与恢复

默认位置：`~/Library/Application Support/CodexUsageMonitor/`。

| 文件 | 作用 | 恢复边界 |
|---|---|---|
| `token-cost-ledger.json` | schema 3 冻结记录/checkpoint | 不应删除，会丢失冻结历史 |
| `session-file-index.json` | schema 3 文件元数据与完整行游标 | 可重建，但会触发昂贵扫描 |
| `analytics.sqlite`、WAL/SHM | 事务性分析投影 | 可重建，不重新计价 |
| `signed-pricing-catalog.json` | 可选签名目录 | 可回退内置版本并披露状态 |

`CODEX_USAGE_DATA_DIR` 只覆盖本工具的数据目录，适用于隔离测试，不改变 Codex 日志路径。
索引与账本通过 revision 绑定；文件截断、重写、未完成 JSONL 行和版本不匹配会安全回退。
SQLite 失败回滚，不是另一个独立费用真相来源。
旧 schema 迁移先备份；仅针对已识别的旧文件名重复键做迁移，合法冻结记录保留。

## 刷新与资源

| 触发 | 正常策略 |
|---|---|
| 启动/唤醒 | 请求最新账户数据和本机增量扫描 |
| 账户轮询 | 60 秒；失败指数退避，上限 30 分钟 |
| 额度通知 | 持续排空 stdout，约 1 秒合并刷新；轮询兜底 |
| 日志事件 | FSEvents 约 30 秒合并，持续写入不无限推迟 |
| 本机扫描兜底 | 15 分钟 |
| 低电量 | 轮询加倍，日志合并约 120 秒 |
| 睡眠 | 暂停；唤醒等待旧任务清理后重启 |
| 手动刷新 | 来源独立刷新，同类重复任务合并 |
| 退出/SIGTERM | 取消任务，关闭管道/helper，不遗留孤儿 |

stdout 限制未闭合行大小和响应队列。只保留一个 app-server，会话不会因面板开关重建。
额度或账户接口返回 401、`token_revoked` 等认证错误时，会关闭旧 helper，
从已配置的可执行文件路径重新连接一次，以加载当前 Codex 登录状态。
重连仍失败时保留其他已成功来源的结果，不无限循环，也不改写 Codex 认证文件。
若 Codex 本身已退出登录，仍需先在 Codex 中重新登录。
文件解析逐行检查取消；索引命中时只检查元数据或新增完整行。

开发机约 2,039 份日志的隔离测试中，暖扫描约 0.4–0.6 秒。
100 秒加速测试 RSS 约 95–102 MB、FD 12–13，退出无 helper 残留。
后续 2026-10-06 的同一冻结样本对比中，2,042 份日志的空索引重建从 103.5 秒降到
60.9 秒；暖扫描约 0.6 秒。这不是跨机器保证，也不是冷磁盘时间承诺。
两小时正常频率资源检查已通过，但不等于电池能耗测量；真实睡眠/唤醒、断网恢复和
干净第二台 Mac 仍未验收。OSLog 只记录耗时、文件数量、连接状态与结果，不记提示词、
token 明细或凭据。完整证据和范围见[验收记录](V2_IMPLEMENTATION.md)。

## 分析和隐私

图表最多展示 90 个有记录日期，汇总用完整筛选范围。缺少日期不等于确认零账户活动。
价格覆盖率 = 已计价 token / 已记录 token；缓存占比只用分类有效的记录。
采集问题另列，计价 100% 不代表全部日志成功读取。

CSV 导出筛选后的精确分类、单价/版本、补估和异常，未计价金额留空。
默认稳定代号替换聊天名和完整 ID，并防止表格公式注入。
去名称图片显示前 10 个聊天组。代号可跨导出关联，日期/模型/金额仍可能敏感。
关闭隐私模式的 CSV 包含真实名称（无标题时可能含编号片段），分享前应检查。
导出不包含提示词和认证令牌。
